# Deployment

Free-tier setup used for the submission:

| Part | Service | Why |
|---|---|---|
| PostgreSQL | **Neon** | Free tier does not expire (Render's free Postgres is deleted after 30 days) |
| API | **Render** web service | Blueprint in `render.yaml`, health checks, HTTPS |
| Web | **Vercel** | Static Vite build with an `/api` rewrite to the API |
| Android | **EAS Build** | Produces an installable `.apk` and a download link |

## 1. Database (Neon)

1. Create a project at neon.tech (region close to your Render region, e.g. Singapore for India).
2. Copy the **pooled** connection string, e.g. `postgres://user:pass@ep-xxx-pooler.ap-southeast-1.aws.neon.tech/neondb?sslmode=require`.

## 2. API (Render)

1. Push the repository to GitHub.
2. Render → **New → Blueprint** → select the repository. Render reads `render.yaml`.
3. Fill in the two prompted values:
   - `DATABASE_URL` = the Neon string
   - `WEB_ORIGIN` = your Vercel URL, e.g. `https://kriya-pms.vercel.app` (you can update it after step 3)
   `JWT_ACCESS_SECRET` is generated by Render.
4. Deploy. The start command applies migrations, then starts the server. Open `https://<api>.onrender.com/api/health` → `{"status":"ok","database":"up"}` and `/api/docs`.
5. Seed the demo account once, from your machine:
   ```bash
   cd apps/api
   DATABASE_URL="<neon-url>" DATABASE_SSL=true JWT_ACCESS_SECRET=x-placeholder-not-used-by-seed-xxxxxxxxxxxx SEED_ADMIN_PASSWORD="<a private password>" npm run db:seed
   ```
   `SEED_ADMIN_PASSWORD` creates `admin@example.com` with a password **you choose and share only with the evaluators** (in the submission email, not the repo). Without it, no admin account is created on a hosted database — the documented `Admin@12345` is for local databases only, because anyone can read a public README.
   To make an existing account an admin instead:
   `DATABASE_URL="<neon-url>" DATABASE_SSL=true JWT_ACCESS_SECRET=x-placeholder-not-used-by-seed-xxxxxxxxxxxx npm run user:role -- you@example.com ADMIN`
   (On Windows PowerShell, set each variable first, e.g. `$env:DATABASE_URL="<neon-url>"`, then run the npm command.)
6. Verify everything end to end: `node scripts/verify-flow.mjs https://<api>.onrender.com` → 29 passed.
7. **Reminder job:** Render generates `CRON_SECRET`. Copy it, then in GitHub → Settings → Secrets and variables → Actions add `CRON_SECRET` (same value) and `API_URL` (`https://<api>.onrender.com`). The **Due-tomorrow reminders** workflow then calls the API every hour; run it once by hand (Actions → Due-tomorrow reminders → Run workflow) to check it returns 200.

**Cold starts.** Free Render services sleep after 15 minutes without traffic; the first request then takes 30–60 seconds. The mobile client waits up to 45 seconds and the web shows a retryable error. Before a demo or review, open `/api/health` once.

## 3. Web (Vercel)

1. Edit `apps/web/vercel.json` and replace `REPLACE-WITH-YOUR-API` with your Render hostname. Commit.
2. Vercel → **Add New Project** → import the repository.
   - Root directory: `apps/web`
   - Framework preset: Vite
   - Install command: `cd ../.. && npm ci --include-workspace-root -w @pms/shared -w @pms/web`
   - Build command: `cd ../.. && npm run build:shared && npm run build -w @pms/web`
   - Output directory: `dist`
   - Environment variables: none needed (`VITE_API_URL` stays empty).
3. Deploy, then make sure `WEB_ORIGIN` on Render equals the final Vercel URL (no trailing slash).

**Why the rewrite?** The browser calls `https://your-app.vercel.app/api/...`, and Vercel forwards it to Render. The refresh cookie therefore belongs to the web app's own domain (first-party), so Safari and other browsers that block third-party cookies keep the session. Without the rewrite you would set `VITE_API_URL=https://<api>.onrender.com` and, on the API, `COOKIE_SAMESITE=none` and `COOKIE_SECURE=true`. That works in Chrome but not in browsers that block third-party cookies.

## 4. Android APK

1. Edit `apps/mobile/eas.json` → `build.preview.env.EXPO_PUBLIC_API_URL` = `https://<api>.onrender.com`.
2. Build:
   ```bash
   npm i -g eas-cli
   eas login                       # free Expo account
   cd apps/mobile
   eas init                        # links the project, adds a projectId to app.json
   eas build --platform android --profile preview
   ```
3. When the build finishes (~10–15 minutes), EAS shows a URL and QR code. Share that link, or download the `.apk` and attach it to the submission.
4. Install it on a phone (allow "install unknown apps") and log in with the demo account.

The APK talks to the HTTPS API, so no cleartext-HTTP configuration is needed.

### Push notifications

Without this section the APK still gets due-tomorrow reminders — scheduled on the phone itself. Completing it switches the APK to real server push (arrives even if the app was not opened that day, and reflects changes made on the web).

1. `eas init` (step 2 above) gives the app an Expo project ID — required for Expo push tokens.
2. Firebase (free): console.firebase.google.com → **Add project** → **Add app → Android** with package name `com.kriya.pms`. Download `google-services.json` into `apps/mobile/` and add `"googleServicesFile": "./google-services.json"` under `expo.android` in `app.json`.
3. Firebase → Project settings → **Service accounts** → *Generate new private key* (a JSON file). Then `cd apps/mobile && eas credentials` → Android → preview → **Google Service Account** → *Manage your Google Service Account Key for Push Notifications (FCM V1)* → upload that JSON. Do not commit this file.
4. Rebuild the APK (`eas build --platform android --profile preview`).
5. On the phone: Settings → Reminders should say **Delivered by push**. Tap **Send test notification** — it goes phone → API → Expo → Firebase → phone.

To see a real reminder quickly: create a task due tomorrow, then (temporarily) set `REMINDER_HOUR` on Render to the current hour in your time zone and run the GitHub workflow by hand.

## 5. Final checks

- [ ] `/api/health` OK and `/api/docs` loads
- [ ] `node scripts/verify-flow.mjs <api-url>` → 29 passed
- [ ] Web: log in, refresh the page and stay logged in (proves the cookie and rewrite are correct)
- [ ] APK: log in with the same account, pull to refresh, see the web data
- [ ] Admin: log in as `admin@example.com` (your private password), open **Admin**, see both accounts; the demo user gets 404 at `/admin`
- [ ] Reminders: Settings → Reminders → Send test notification arrives on the phone
- [ ] Fill in the URLs at the top of `README.md`

## Docker (optional, any VPS)

```bash
docker build -f apps/api/Dockerfile -t pms-api .
docker run -p 4000:4000 -e DATABASE_URL=... -e DATABASE_SSL=true -e JWT_ACCESS_SECRET=... -e WEB_ORIGIN=... pms-api
```
